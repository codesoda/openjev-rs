# Tagged CI releases and downloaded-artifact acceptance

Parent/Astra release design. This implements the active goal: CI builds releases from tags and an actual downloaded release is installed and smoke-tested. It is separate from unfinished M6 benchmarking and M7 calibration/permutation work.

## Contract

Deliver a tag-triggered GitHub Actions pipeline for `codesoda/openjev-rs`, publish source-versioned binary archives with SHA-256 checksums, then download/install the macOS archive from GitHub Releases and run real offline cached-model Metal HTTP plus official SDK tests against that installed artifact. Never substitute a local rebuild for the downloaded artifact. Do not change model/core semantics, native pins, parity tolerances, or reference files. No GGUF redistribution or re-download of healthy models. Preserve repository privacy. Use standard GitHub-hosted runners only; do not change billing or create paid larger runners. If Actions is unavailable due to billing/permissions, report the actual blocker rather than bypassing CI or manufacturing success.

## CI/release design

- Standard private-repo runner labels verified from https://docs.github.com/en/actions/reference/runners/github-hosted-runners: `macos-14` is arm64/M1 and `ubuntu-22.04` is x86_64. Pin these OS labels, not latest. Rust toolchain 1.95.0 matches workspace rust-version. Install rustfmt/clippy. Linux needs CMake, clang/libclang and C++ build tools; macOS system Xcode supplies build tools. Verify architecture in jobs.
- Run on push to main, pull requests, and `v*` tags; a manual dispatch can exercise the same build without publishing. Main/PR runs check fmt, workspace all-target clippy with warnings denied, workspace tests with target's native feature and integration feature compiled but `OPENJEV_INTEGRATION` unset (no model downloads). Preserve exact prompt-hash unit goldens.
- Build release binaries on both platforms, `--locked`, with CLI Metal on macOS and native CPU on Linux. No `target-cpu=native`: portable CPU settings, not host-specific instruction assumptions. On Linux explicitly disable optional x86 AVX/AVX2/FMA/F16C/BMI2/SSE4.2/AVX512 settings if selecting baseline generic x86_64. Verify real pinned sys source before flags: it forwards GGML_/CMAKE_ env settings, but explicit Rust target features later override corresponding flags.
- `llama-cpp-sys-2=0.1.156` currently builds static libraries by default. Enable `GGML_METAL_EMBED_LIBRARY=ON` on macOS; its bundled CMake embeds the Metal library/source instead of requiring runtime files from a build directory. Set and document macOS deployment target 14.0. End users must not need Xcode/Homebrew/Python to execute the binary. Do not claim Apple notarization or Developer ID signing.
- Packaging sanity: JSON `--version`/`--help`; `file`; macOS `otool -L` must contain only system frameworks/libraries, not build/Homebrew paths. Linux `ldd` must resolve all dependencies and docs declare glibc >=2.35 plus system libstdc++/libgcc requirements if dynamically linked; do not advertise static-musl portability. Execute binary from an extracted archive outside the checkout as an extra packaging check. Linux inference execution is a separate future runtime gate unless actual model smoke is run.
- Archives: `openjev-v<VERSION>-aarch64-apple-darwin.tar.gz` and `openjev-v<VERSION>-x86_64-unknown-linux-gnu.tar.gz`, containing a versioned directory with `openjev`, LICENSE, THIRD_PARTY.md, README/SERVE usage or release-specific README, and BUILD-INFO.json (source SHA, tag/version, target, native pin, Rust version/backend, system requirements). No model weights, keys or machine cache data.
- Produce SHA256SUMS over the exact archive bytes and publish only after both build/test jobs pass. Validate tag format/version against workspace version before publishing. Release publication uses tag commit, never branch HEAD; record workflow run URL/source SHA. On main/PR/manual runs upload ordinary workflow artifacts but don't create a GitHub Release.
- Use pinned action SHAs. Verified current v4 refs: checkout `11d5960a326750d5838078e36cf38b85af677262`; upload-artifact `ea165f8d65b6e75b540449e92b4886f43607fa02`; download-artifact `d3f86a106a0bac45b974a628896c90dbdf5c8093`; cache `0057852bfaa89a56745cba8c7296529d2fc39830` if needed. Minimal workflow permissions contents:read; contents:write only for tag publish job. No pull_request_target, no untrusted-input shell interpolation, no personal access token needed for publishing. Use checkout's no-persist credentials for build jobs when practical.
- Do not overwrite published assets or move tags. A failed unreleased tag can be retried only if source/config do not change; fixes require a new commit/version/tag. Publish initial v0.1.0 only after main CI has proven the exact packaging path. GitHub-hosted native compilation can take minutes; retain failures and fix causes, not tests/tolerances.

## Download/install/smoke gate (parent after CI publication)

1. Confirm release tag/commit equals passing CI run and both archives plus SHA256SUMS are attached to the GitHub Release.
2. Download macOS archive AND checksum file from the release with `gh release download`, not local target/artifact substitution. Verify SHA-256 and archive traversal-safe members before extraction. Compare binary hash to packaged BUILD-INFO/CI metadata where recorded. Retain downloaded archive and evidence in a user cache location, not git.
3. Install versioned binary under `~/.local/share/openjev/releases/<tag>/...`, with an `~/.local/bin/openjev` symlink. Check before replacing anything; back up an existing binary or symlink and do not overwrite unrelated files silently. No sudo needed. Document PATH if this directory is absent from shell PATH. This session observed no existing `command -v openjev` result, but re-check filesystem paths.
4. Execute installed binary from a temporary directory outside the checkout with model cache explicitly selected/offline, explicit Metal, server bound to loopback. Avoid DYLD/library/model path hacks. Verify version, readiness, repeated raw HTTP mixed questions, fallback disclosure, empty stdout, one resident load and SIGTERM shutdown.
5. Run pinned official SDK script against the installed release server. Verify three types, model list, probabilities/rounding/Score legend, input/output token usage, wrong-key 401, unknown-model 404 and unsupported-float 422. Capture installed binary SHA, download URLs, release/tag/CI SHA and run URL, native device logs and sanitized request results. This proves the downloaded artifact, not complete performance or every model/OS.
6. Re-run fmt/clippy/tests locally for release tooling changes, record PROGRESS/RESULTS/README/todo and commit/push. Smoke evidence may be a follow-up documentation commit after the immutable release tag; distinguish source release SHA from evidence commit clearly.
7. Mark the active release goal complete only after all above evidence is verified and pushed. If blocked, stop with failed runs/logs, attempted fixes and exact next user input; never call goal complete for a locally built artifact alone.

## Review and iteration

Sol implements workflow/packaging scripts against this full plan file. Parent/Astra reviews workflow permissions, version binding, packaging/linkage and test gates before push/tag. Observe Actions via an event-driven monitor or a bounded blocking `gh run watch`, not constant busy polling. On failure inspect exact job logs, change only the implicated build/package code, run local checks, commit, and re-run. No changes to native parity or model caching to force CI green. Do not enable any failed shared/batch profile. A release remains the documented Jev subset, uncalibrated and not hosted Jev intelligence parity.
