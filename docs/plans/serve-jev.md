# Resident Jev-compatible HTTP extension

Status: design approved by parent/Astra; the official pinned SDK's `src/types.ts` and `src/client.ts` have been fetched and checked directly. Final native HTTP/SDK execution and code-review acceptance are recorded in `docs/PROGRESS.md`. This user-requested extension supersedes the original v1 HTTP-server non-goal, not the direct prompt/parity requirements. Read `docs/PLAN.md` and this document in full before implementation.

## Outcome and boundaries

`openjev --serve` loads one selected, verified model once, accepts Jev-shaped HTTP requests, and returns lean typed answers. Existing CLI commands/output are unchanged. No sampling, model switching per request, silent CPU fallback, disabled-probe bypass, altered M3 golden bytes, or new parity tolerances. Server residency saves startup/loading, not proof of parallel inference. The shared/batch numerical investigation remains a separate task; existing safety fallback must remain observable.

Work in this repo only. Preserve references and immutable result captures. Reuse cached GGUFs and existing `target-m2-metal`/`target-m2-cpu`; no redownloads or hours-long benchmarks. M6 remains partial and M7 outstanding. Existing work was checkpointed separately before this extension.

## Stack and ownership

- Confirmed crates.io/source: axum 0.8.9 and tokio 1.53.1. Pin versions; read downloaded crate APIs before use. Keep HTTP code in CLI modules `server/` and a separately testable Jev adapter; no core HTTP dependency is needed.
- Existing `commands::NativeScorer::load` owns one `EngineHandle`; the native worker loads the model once. Construct a scorer once on a dedicated synchronous inference-owner thread. Do not call `load_scorer` per HTTP request. Do not hold stderr locks while native callbacks log.
- Use an async HTTP frontend and bounded channel, owned request/reply objects, and no unsafe Send/Sync. Create the trait object inside its owner thread rather than requiring unrelated trait changes.
- Startup binds/serves only after successful model load (and a small disclosed warmup). On failure exit nonzero; never advertise ready. Bind errors should be discovered before expensive startup where practical; accepting begins only after ready.
- One inference owner initially. At most 16 admitted jobs including running work; reserve an admission slot before body buffering, and enforce a 1 MiB body cap even for chunked bodies. Validate the entire request before inference. Maximum 64 questions and 16 options; no implicit truncation. Before per-question state cloning, also cap Python-serialized state bytes multiplied by total question count at 4 MiB (including deterministic questions conservatively). This bounds expansion of one large structured state into many owned trees before native token checks; excessive requests return 422. Admission includes body-reading requests. Return 429 plus Retry-After when full. Keep queue/admission logic testable with injected workers.
- Total request deadline default 120s, configurable and positive; includes reading/queueing/inference. Drop timed-out/disconnected queued jobs before execution. Once native work has started it may not be interruptible; keep admission capacity charged until it really completes. Stop between questions when abandoned. Do not claim GPU cancellation.
- SIGINT/SIGTERM stop admission/listening, signal pending jobs, and gracefully join/shutdown the scorer. Document that an in-flight native decode is noninterruptible. Bound client/body handling via deadlines; queued jobs must not keep shutdown busy doing unnecessary inference. Worker termination must mark readiness unavailable, not leave hanging reply receivers.

## CLI and HTTP surfaces

- Exact requested spelling `openjev --serve`; optionally also `openjev serve` if convenient, but not necessary. Default host 127.0.0.1, port 8080. Existing global `--model`, `--device`, `--cache-dir`, `--offline`, context/thread settings apply.
- Add `--host`, `--port`, `--request-timeout-secs`, and optional `--api-key-env NAME` (environment variable value is the secret). Server flags without --serve, --serve plus a command, and decision-format-only flags with --serve must error before model load. No argv token rewriting that mistakes option values for flags. Preserve structured JSON help/version/errors and examples.
- Loopback without auth accepts a dummy SDK bearer token. Non-loopback binding requires explicitly configured nonempty bearer auth; no insecure override is needed. Do not log secrets or request contents; do not enable wildcard CORS. TLS belongs at a reverse proxy. Health may remain unauthenticated; protect model/inference routes when auth enabled.
- `POST /v1/systemone`, `GET /v1/models`, `GET /healthz`, `GET /readyz`. Unsupported paths/methods, bad media types, oversize bodies, parse/validation/auth/overload/model errors must have JSON error bodies. Startup and access diagnostics go to stderr; no human text on stdout.
- Content-Type application/json (charset allowed). Response errors include a stable `error_type` and `message` compatible with SDK parsing; appropriate 400/401/404/405/413/415/422/429/500/503/504 status. Client input errors must not leak local paths/native details. Native slot verification failure stays an explicit backend failure.
- `/v1/models` lists only the loaded actual local identity with SDK-required fields (name, description, release_date), not unavailable models or fabricated TypeSafe versions. Document any release-date convention honestly.
- Requested model may be omitted/defaulted as official contract allows, or match loaded ID. Accept `jev-latest` as a documented routing alias to the selected model; do not silently accept arbitrary unknown models. Response `model` is actual loaded identity, never impersonating Jev. Do not expose arbitrary custom artifact local paths in HTTP metadata.

## Wire adapter

Verified `typesafe-ai/typesafe-sdk-js` commit `66880ccded6cb642dc1809620c2b108c33730214`, package 0.6.0, against its actual `src/types.ts` and `src/client.ts` (not only a prior research summary). Implement a supported Jev wire subset, document restrictions rather than claiming hosted parity.

Request: `{model,state,questions:{question_id:{type,instructions?,criteria?}}}`. State and EntryType instructions/criteria accept string/object/array/null per SDK. Preserve map insertion order. Reuse `parse_json_strict` for duplicate rejection, integer lexemes and bounded depth: floats in JSON state/instructions/descriptions remain explicitly unsupported (422) pending separate Python-float parity work. Never stringify a whole structured state to silently bypass validation. Unknown behavioral fields should be rejected if unsupported, not silently interpreted.

Map arbitrary external question IDs to stable internal nonempty IDs and map back. Instructions strings are preserved; structured entries use `python_json_dumps`; omitted/null/empty instructions use a documented nonempty default, e.g. `Select the best option.`. Descriptions: string verbatim, structured/null via documented Python JSON rendering; null Choice description can use its semantic option label if official semantics warrant it, but pin and test the chosen mapping. No hidden labels/options.

- Choice: insertion-ordered criteria map -> semantic option IDs and descriptions. Response `{type:"choice",choice,confidence,probabilities:{label:p}}`. One-option choice is a deterministic adapter result (probability/confidence 1, zero inference tokens); never add a fake second option. Reject zero or >16 options explicitly.
- Score: ordered criteria array (2..16) -> IDs `"0"..`, values 0..K-1. Response `{type:"score",score,confidence,legend:{"0": original_description,...},probabilities:{"0":p,...}}`; score is expected index, not argmax or 0..1 normalization. Preserve legend original JSON types.
- Noul: default Yes/No slots preserve openjev's existing yes-first convention; optional true/false criteria map to these options (custom descriptions supported). Response `{type:"noul",noul:p_true}`. Do not call `Noul::new` and lose custom criteria; use an explicit Decision/projection when necessary.
- Choice/Score confidence uses existing `normalized_margin`, clearly labeled conditional/uncalibrated in documentation and headers; don't import Laya's entropy formula. Use original probabilities for expectation/confidence and first argmax. Round displayed probabilities, Noul value, Score value and confidence to two decimal places in the wire projection only; rounded distributions need not sum exactly to one and must not be renormalized. Never modify core readouts. Source: Vercel `ai` pin `20dd00abba618d5a516e0fee40ccd3e18a2bd1fb`, `packages/typesafe-ai/src/typesafe-ai-evaluation-model.ts` declares `rounding: { probabilityDecimals: 2, scoreDecimals: 2 }`; its `typesafe-ai-evaluation-api.ts` validates these Jev response fields. Parent fetched both pinned raw sources during this extension.
- Response envelope `{model,answers,usage:{input_tokens,output_tokens}}`. Input tokens count logical full decision prompts (sum of readout input_tokens, including repeated state per question); this is not unique KV-prefix work or a hosted billing measure if sharing becomes eligible. output_tokens=0 because no generation. Skip deterministic one-option questions in inference accounting.
- Response schema stays lean; disclose requested/effective execution and fallback reason in bounded safe ASCII HTTP headers (e.g. X-OpenJev-Execution, X-OpenJev-Fallback) and stderr, and conditional-probability status via header/docs. Never put request-derived text or raw newlines into headers. No promise of numeric equivalence to hosted Jev.
- Several inferential questions request shared execution using existing `attempt_native_group`/receipt rules with bounded groups; on unavailable/failing shared path discard tentative results and use direct serial with explicit metadata. `--require-shared` preserves fail-closed behavior: fewer than two inferential questions are rejected without client inference; multi-question requests require a passing receipt, otherwise return a typed unsupported error without serial fallback. Without that flag, one-question requests use direct. Reuse a extracted resident-scorer helper rather than duplicating the whole one-shot load/shutdown pipeline if feasible.

## Acceptance gates

1. Unit adapter tests: all three types, arbitrary/unicode IDs/labels, structured/null entries, optional instructions/criteria, singleton Choice, ordering, ties, score expectation, usage, rounding, duplicate keys, depth/float/size/count invalids. Invalid whole request must make zero inference calls.
2. Router/worker tests with injected deterministic scorer: model load exactly once for multiple requests; worker shut down once; no cross-request state leakage; readiness; auth and nonloopback validation; malformed/oversized/chunked/media-type/unknown-route errors JSON; bounded overload; queue timeout/disconnect cancellation; capacity stays charged during noninterruptible work; graceful shutdown/error readiness. No network/model dependencies in default unit tests.
3. Real official pinned JS SDK against local HTTP. Test Choice/Noul/Score, models, errors; document SDK root base URL and nonempty dummy API key. Keep reproducible pinned compat smoke script and lockfile/source provenance. A test stub may prove protocol wiring, but at least one real native server smoke must back production-readiness claims.
4. Build Metal release in existing target, use cached offline Qwen3-0.6B, send repeated HTTP requests and mixed primitive request, verify same resident model/healthy process, stdout policy, serial disclosure, SIGTERM shutdown. Opt-in native test guarded with `OPENJEV_INTEGRATION=1`; don't benchmark concurrent with another project.
5. `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`; Metal-feature clippy/tests and bounded native server smoke. Existing prompt goldens and CLI tests must remain passing.
6. Parent/Astra reviews actual changes and evidence before commit. Update README, docs/PROGRESS.md, todo.md and schema/source credits. Record compatibility limitations and outstanding independent shared-path/M6/M7 work. Commit extension separately; no claim entire original project is complete.

If pinned source contradicts the provisional wire mapping, stop that point, report evidence to parent and amend this plan before implementation of the disputed behavior. If native smoke is blocked, publish passing non-native checks and the exact blocker; do not invent a working server or speedup.
