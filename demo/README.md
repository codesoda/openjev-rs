# README recording (VHS)

The README uses [`docs/demo.gif`](../docs/demo.gif), with a higher-quality
[`docs/demo.mp4`](../docs/demo.mp4) alternative. Both are generated by
[Charmbracelet VHS](https://github.com/charmbracelet/vhs). Styling follows the
Discuss CLI's terminal scenes: Catppuccin Mocha, a 1280px-wide terminal, and a
scripted, reproducible recording rather than hand-recorded terminal input.

## Re-record

Prerequisites:

- A current native `openjev` on PATH with `serve` and `demo` (not v0.1.0).
- Qwen3-0.6B already cached: `openjev models pull qwen3-0.6b` (one-time).
- VHS, ttyd, FFmpeg, Python 3, and a browser supported by VHS. On macOS:
  `brew install vhs ttyd ffmpeg`; Menlo is the recording font.

From the repository root:

```sh
bash demo/record.sh
```

The wrapper starts its **own** loopback server on port 18787, waits for readiness,
then runs `vhs demo/readme.tape`. It uses `--offline`, Qwen3-0.6B, and Metal on
Apple Silicon macOS (CPU elsewhere). It refuses an occupied port; set
`DEMO_PORT=18788` to use another. It never attaches to or shuts down an existing
server, and cleans up its child on exit.

The tape executes the real command:

```sh
openjev demo --base-url "$DEMO_URL" --quiet | python3 demo/present.py
```

`present.py` reads each live JSONL response and displays a **compact projection**:
example, model, typed answer values, and rounded HTTP milliseconds. This is a
recording-specific presentation, not the complete Jev response or a new CLI
output schema. Full probabilities, confidence, Score legends, usage, and other
metadata remain in `out/demo-recording/responses.jsonl`; fallback disclosures
also appear onscreen. Use `openjev demo --pretty` for the normal full output.

## What the recording proves (and does not)

- Eight real HTTP requests; no mocked, edited, or precomputed predictions.
- The model was loaded before capture. Startup time is **not** shown.
- Cards pause for reading; playback is **not** an inference speed benchmark.
  `http_ms` comes from the real client's round-trip measurements.
- The model can be wrong. Probabilities are conditional and uncalibrated; Score
  is the expected zero-based level index. No result is replaced to look better.
- The mixed request honestly displays the current shared-to-serial fallback.

The checked-in capture was made on an Apple M3 Pro using the local Metal build.
It is about 33 seconds, 1280 × 860, with a ~315 KiB GIF and ~310 KiB H.264 MP4.
Logs, unmodified response rows, and the final-frame PNG stay in ignored
`out/demo-recording/`. Review those and sampled video frames before committing a
new recording. These features are not yet in the published v0.1.0 binary.

Quick checks:

```sh
shellcheck demo/record.sh
python3 -m py_compile demo/present.py
vhs validate demo/readme.tape
ffprobe -v error -show_entries format=duration,size -of json docs/demo.mp4
```
